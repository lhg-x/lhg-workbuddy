# benchmark-distill

授权：调用即授权从拆解做到报告交付，中途不问确认。仅在"视频无法读取"或"脚本连续失败两次"时停下。

## 输入
- `template/` 下的视频文件（1 条或同系列多条，越多越能分清共性 vs 偶然）。
- 可选：对标在 `data/benchmarks.csv` 中的行（带数据）。

## 第 1 步 机器拆
```bash
uv run scripts/analyze_video.py template/<file>.mp4 --out teardowns/<date>-<slug>
```
产出 `analysis.json` + `contact_sheet.jpg` + `keyframes/`：
- 镜头表（硬切时间、镜头时长、平均镜头长）
- 每秒运动强度（找最猛的几秒 = 高潮候选）
- 主色板 + 强调色（彩色像素单独统计）
- 响度（LUFS / 峰值）、BPM 估计、重拍时间点

## 第 2 步 人眼拆（看图）
1. 通看 `contact_sheet.jpg`，把画面分类：标题卡 / 图表 / 实物 / 大字 / 角色 / 转场。
2. 逐张看关键帧：字体气质、描边、发光、字号层级、版式位置、留白。
3. 入场/转场/招牌动作：从关键帧附近抽帧（`ffmpeg -ss T -t 1 -vf fps=30`），数几帧完成、缓动、有无模糊缩放。
4. **对齐卡点**：把运动峰值、硬切时间和重拍时间对表，标出"画面跟拍"的位置和高潮位置；检查是否有"收暗 → 静止 → 砸"的结构。

## 第 3 步 内容结构拆
- 逐段转写（可用 whisper 或让用户提供字幕），只用于分析，**不复制进作品**。
- 拆：开头钩子（前 3 秒说了什么）、问题抛出时间、信息点密度（几秒一个）、高潮位置、锚词、结尾提问。
- 评论区：主要争论点是什么 → 是否能在我的版本里放大。

## 第 4 步 写报告
用 `templates/teardown-report.md`，写到 `teardowns/<date>-<slug>/report.md`，必须包含：
- 风格配方卡（配色/字体/版式/转场/节奏/招牌画面）
- **没有搬的东西**（原文案、字幕、配乐、水印、人名）
- **超越点**：画面冲击力 / 视觉感染力 / 卡点 各给 1–3 条具体改法
- 适配我的生产线：映射到火柴人（stickman-director）或手绘费曼（feynman-teach）的哪些组件/风格

## 第 5 步 自检
- 报告里的每个时间点能在 `analysis.json` 里找到依据。
- 音频只报数字，提醒用户戴耳机确认调性。
